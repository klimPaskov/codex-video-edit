# User example video acceptance prompt

Use the user-supplied example video as the final product acceptance fixture.

1. Launch the installed native app in the isolated test environment.
2. Import the video through the real file-picker flow or a deterministic test stub that points to the exact supplied file.
3. Record the source hash and probe result.
4. Sign in to real Codex if the environment is authorized. Do not simulate it.
5. Run the Balanced Magic Wand preset.
6. Watch the complete edited draft with audio.
7. Inspect cuts, meaning, zooms, speed-ups, captions, cursor treatment, framing, B-roll, and audio.
8. Fix every material defect through visible manual tools or natural-language Codex edits.
9. Run QA and resolve blocking failures.
10. Export the lossless master, fully decode it, and verify canonical sample equality, duration, streams, sync, captions, and hash.
11. Save native app screenshots, a short interaction recording, operation summary, repair notes, QA report, and final manifest.
12. Update package contracts for any workflow lesson discovered.

Do not call the result improved unless the report explains what changed and the full watch-through supports it.

Export the lossless master from original or verified lossless sources, prove equality to canonical edited samples, and preserve the original recording. Test a smaller MP4 only as an explicit separate profile. Keep the user example and all private visual evidence out of public Git history.

## Editorial acceptance

Apply `docs/47_EDITORIAL_FIRST_CUT.md` and `prompts/EDITORIAL_FIRST_CUT_PROMPT.md` in addition to the existing feature checks. Inspect real source/sync/protected scope and approved layouts; use one actual transcription job; conservatively resolve spoken instructions and retain ambiguity. Verify final complete retakes, every cut join, whole-source omission review, full edited-transcript reread/restoration, purposeful layout sections and named zooms with boundary/midpoint/interior evidence.

Deliver selective graphics opportunities with final-cut timing and complete prompts only; do not generate/import graphics from the edit request or recorded cues. Verify protected material and source hashes, actual counts and committed/checkpoint state. The export step above is the separately requested final acceptance operation, not an automatic Magic Wand side effect. Use the required explicit native export action; suggestions and pass checkpoints never authorize export. Report unavailable or unresolved checks truthfully and preserve private footage/evidence.
