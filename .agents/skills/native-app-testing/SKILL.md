# Native app testing

## Use when

A phase changes UI, recording, media playback, Codex interaction, or packaging.

## Procedure

1. Verify the isolated environment using `python scripts/desktop_environment.py check`. Follow `tests/desktop/README.md` for provisioning and the sandboxed compatibility probe. Keep probe evidence distinct from product acceptance.
2. Build and launch the current desktop app in the agent's isolated desktop environment.
3. Use Playwright Electron for repeatable navigation, dialogs, controls, state, and screenshots.
4. Inspect and operate the actual guest native window with `tests/desktop/guest-input.py`, running only inside Docker. Observe the guest screenshot, choose one action, and inspect its returned screenshot. All native input and screenshots stay in the guest; no host computer-use or viewer control.
5. Use virtual capture devices for deterministic recording tests.
6. Watch rendered media with audio.
7. Record build hash, test environment, steps, screenshots, short recordings, and failures.
8. Fix defects and rerun the same path.

For the P0-04/P0-06 bootstrap, apply ADR 0012 and test the actual packaged product: native import, immutable managed source, library reopen, frame seek/equality and explicit unsupported-preview behavior. Keep the media library distinct from a project or draft. The compatibility probe verifies infrastructure only. Record product runtime evidence separately; frame inspection does not establish audio or continuous playback.

For interface sizing changes, test persisted zoom after restart, modal focus and dismissal, and inspector bounds alongside the preview at every supported size. Inspect the actual native window after saving a larger scale: focus restoration can scroll navigation out of view even when a screenshot has no horizontal overflow. Keep this visual check separate from pixel transport equality.

For the managed-login opener, use a guest-local browser/URL handler under the same unprivileged, no-mount, no-port policy. Launch packaged Electron from a fresh signed-out account with the real `shell.openExternal` path, inspect both guest browser and native window with `guest-input.py`, cancel back to signed out, and terminate only test-owned guest browser/opener processes. A loaded OpenAI login page proves opening, not account-login completion. Keep OAuth URLs, codes, browser profiles and screenshots private.

For the optional device-code route, separately test start, transient Settings code, fixed-page opening in the guest browser, cancellation and test-owned process cleanup. To verify managed completion, use the official App Server attempt and observe its completion in the same native app after the user verifies externally; require reconciled signed-in account and cleared code. Reopen packaged Electron with that private app-owned account and compare authoritative account/plan, runtime models and skills. A completion that arrives during a test written to cancel is a failed cancel assertion for that run, not evidence to erase; retain it alongside the separate completed-login and cancellation outcomes. Never publish the one-time code, account identifiers or private screenshots.

## Prohibitions

- Do not build or launch the product on the user's host, control the host PC, or capture host windows. The latest user instruction supersedes the earlier viewer exception. Historical viewer evidence remains historical; future host-viewer use requires a new explicit user request.
- Do not mount host files, credentials, display sockets, or devices into the guest. Transfer only reviewed source and expressly authorized private test inputs; transfer the supplied video privately only after the relevant fixtures pass. ADR 0006 records this session's narrow user-authorized transfer of only the official runtime credential file into the private app-owned guest account with mode 600. It grants no host UI access, account-directory/configuration/history copying, general credential import or secret output.
- Do not disable Chromium sandboxing or use privileged containers. Run the desktop as the unprivileged guest user.
- Do not substitute a browser page.
- Do not call a DOM assertion visual proof.
- Do not call a virtual device full hardware coverage.
- Do not count the Linux compatibility probe or guest screenshots as Windows product, capture, installer, or audio-listening acceptance.

For screen-reader regressions, preserve failed runs and compare unmodified upstream releases in separate isolated environments. Pin and verify downloaded source hashes. Record exact reader/AT-SPI versions, package and test hashes before startup, confirm supported settings through real API readback, and require both actual reader output and application-owned focus events. Buffered debug text is not a reliable readiness signal. Inspect the visible monitor after it paints; a stale screenshot must remain identified as stale. Never alter the product or reader just to manufacture a passing announcement.

ADR 0013 makes the real project foundation the next P1 shell prerequisite. Test actual create/open/reopen, a resolving baseline revision, source-matched rational timing and persisted five-stage navigation without fake projects or implied stage execution. P2's shared transaction prerequisite remains separate work.

For the implemented project shell, verify Projects and Source library remain distinct; import/create/open/reopen operate on actual records; every stage saves before selected state changes; failure and delayed replies preserve the active project, source and frame position. Compare immutable baseline/source state across navigation and restart. Inspect compact stage controls at 100–200% with guest-only input/capture, including keyboard focus after success, failure, Home and Settings. Visiting a stage cannot count as running its later feature. Keep complete-probe/store tests separate from native visual acceptance. At enlarged interface scale, verify screenshot coverage before judging layout: cropped Playwright PNGs cannot prove the whole window. Use full guest-display screenshots for whole-window visual review, retaining original images privately. Record an unexplained launch timeout and any unchanged retry separately; a later pass does not establish the timeout cause.

For committed-draft preview changes, precommit a real fixture transaction while the packaged app is closed, reopen through the visible project card, and verify duration, seek bounds and decoded source-offset pixels. Confirm the same Source library item still starts at source time zero and source/baseline hashes remain unchanged. Unit tests must also cover a draft change before and during decode; native reopen does not replace the authenticated live-tool gate.

For a new H.264 still-frame path, use a tagged synthetic H.264/AAC fixture first. Import through the packaged native picker, check source/managed hashes, exact decoded-display canvas pixels at multiple times, reopen, and inspect the guest native window with `guest-input.py`. Only after those fixture checks pass may the explicitly supplied private recordings be copied to an isolated no-mount guest and exercised through the same native picker. Keep their screenshots, paths, hashes, and projects ignored/private; a first-frame pass does not prove playback, two-source append, export, or full user-media review.

For a two-source import slice, first prove ordered join frames, trim/undo reflow, reopen and immutable source/baseline integrity on synthetic compatible media in packaged Electron. Only then import supplied recordings through the packaged native picker inside the isolated guest. Compare decoded-display bytes before and at the join, reopen, and inspect both sides of the native preview visually. Keep private footage, hashes, paths, projects and screenshots outside Git. This does not prove synchronized audio, full watch-through, AI editing or export.

For manual Edit controls, use the packaged native window to select Edit, move within a clip, trim an edge and observe committed duration/clip boundaries, then undo and reopen. Check that the next action follows a changed clip map and that invalid boundaries are disabled. Compare immutable source/baseline bytes; guest-only visual input must inspect actual enabled/disabled states. A DOM button click alone does not prove the native preview changed.

For the partial Split action, begin with synthetic compatible footage in packaged Electron. Seek to a true interior position, split, verify two committed fragments and unchanged total duration, seek and compare decoded-display pixels on both sides, trim a resulting fragment to prove current-map targeting, undo through the shared journal, and reopen. Check disabled split at fragment edges and while a save is pending, and compare original/managed source plus baseline integrity. Inspect the actual guest native window with guest-only input before exercising the supplied private footage in order. Keep private frames, hashes, paths and screenshots ignored; a split still-frame pass does not establish synchronized audio or master rendering.

For guarded `cut.split`, additionally require a real authenticated Codex turn in the packaged isolated guest. Observe the committed fragment map while the turn runs, compare exact decoded pixels on both sides of the split and at the next source join, then use the same manual newest Undo and reopen path. Wait for asynchronous Undo settlement before asserting its journal and view. Inspect the actual guest Codex drawer and reopened Edit window with guest-only capture. A model statement or synthetic provider response is not evidence of an applied split.

For a marked ripple range cut, first use two synthetic compatible sources in packaged Electron. Mark in/out on the committed output clock so a valid half-open cut crosses the source join; verify shortened duration, exact surviving frame pixels at the new join, fragment reflow, newest Undo, reopen and unchanged immutable inventory/baseline. Domain tests additionally cover a cut removing one whole visible source span, boundary/whole-draft rejection, stale-head invalidation and deterministic replay. Inspect the actual guest window and visible enabled/disabled states with guest-only input at default and enlarged scale. Only after the synthetic native fixture passes, repeat the cross-source range cut and Undo with the supplied recordings in order in the no-mount guest; keep private footage, paths, hashes, projects and screenshots ignored. A still-frame pass does not establish synchronized A/V editing, a full watch-through or master export.

Keep seeded-account discovery distinct from managed device-code completion and browser OAuth callback completion. After the authorized seed, use private synthetic fixtures for real native turns, guarded edits, committed-state/preview verification, interruption, history reopen, stale rejection and shared undo. A production guarded-service stale check against a real packaged Codex-created native draft can prove offline freshness without another model call; label live stdio relay separately. Verify tool restrictions and native subagent inheritance separately with an authoritative parent rollout spawn call/output, `thread/read` child parent/source, completed child-owned tool history and matching saved read-only/never-approval turn contexts, not model text or generic drawer activity. Pinned v1 persisted turn history omits collaboration items; a bare audit `thread/resume` can overwrite effective settings. Report actual results without secrets, account identifiers or private locations; a connected account and runtime catalogs alone do not satisfy the other P2 gates. Production onboarding remains managed ChatGPT sign-in.

For a negative live tool-policy probe, request a harmless forbidden command on a synthetic project, then check the settled native projection, persisted server item types, and the exact turn's bounded private rollout for raw tool-search/function/other call items that turn history omits. Confine rollout reads to the isolated account and publish only counts or classifications. Select a discovered model in packaged Settings if the guest account has no saved choice. A model refusal and zero observed calls prove only that this turn did not invoke a forbidden tool; they do not prove every built-in was absent from the model-visible catalog. Audit resume with the same production policy overrides, since a bare separate resume can reapply defaults and does not describe the original live turn. Keep failed attempts and guest-only visual records private.

For signed-in Settings, compare displayed plan, runtime model, usage windows/reset labels and available skills with the current bounded IPC state before and after restart. A seeded account can verify presentation but cannot prove managed browser-login completion. Keep account screenshots private and use guest-only input for a visible control change.

For API-provider remembered-model acceptance, use the separate keyring-enabled isolated guest in `tests/desktop/README.md` and `tests/desktop/run-keyring-model.sh`. Assert packaged Electron and the real `gnome_libsecret` backend, transfer an authorized test credential only into a mode-600 guest file, then check live discovery, protected restart, blank renderer key field, guest-only visual state and Remove key cleanup. Record a failed setup separately; never count a fake secure-storage unit test or a browser tab as native keyring evidence.

For the packaged provider draft route, run `tests/native/api-provider-draft-fixture.test.ts` for OpenAI and with `--deepseek` or `--gemini` in the unprivileged guest. Its deterministic main-process transport prevents any paid request; for each provider verify the actual imported project, visible trim while the turn runs, stale rejection, shared undo, provider failure, source/baseline integrity, reopen and guest-only screenshot. The Gemini route also checks exact transient thought-signature replay. Retain timing failures separately and require a complete passing rerun. This does not replace live authenticated provider acceptance.

For an authorized live API-provider fixture, use `tests/native/api-provider-authenticated-edit.test.ts` only in an isolated packaged guest with a mode-600 private key file. The harness reads and deletes that file before Electron launch, observes only HTTP status codes, and sends through the native drawer. A 429 with no journal transaction is an access-limited failed edit, even if model discovery succeeded. Test the fixed message separately with the synthetic native route; keep both records distinct and private. Do not rerun paid completion while the same account returns 429.

The same live harness accepts `--deepseek` and `--gemini` with separate private key files; never substitute one provider's key or a synthetic catalog for authentication. One authorized DeepSeek packaged turn passed live catalog, guarded trim, exact native preview, immutable source/baseline and reopen. Gemini's live route requires a reviewed Gemini 3 model and checks that every observed opaque function-call signature is replayed exactly, recording only counts and a mismatch flag. No Gemini key or live acceptance exists yet. For deterministic 401/403 and 429 recovery, test the actual packaged OpenAI, DeepSeek and Gemini drawers, journal and project reopen. At 1366×768 assert the alert is wholly within the selected drawer and in the viewport, and that the conversation has a usable independent scroll area. Inspect guest-only screenshots: DOM text presence alone missed a clipped alert. When resizing the native window, avoid fixed absolute screenshot pixels; scan the known fixture preview region or derive its real screen coordinates. Retain earlier failed visual runs separately.

For 200% interface-scale regressions, save the actual Appearance setting through the native UI and bring the preview into view before its X11 frame capture. The fixture window cannot display the entire preview and long drawer together at this scale; test their readable states separately, ensure the alert scrolls into view, and require at least 80 CSS px of independently scrollable conversation history. Do not count a text-present but collapsed history as a visual pass.

For the Luna subscription default, test the exact packaged 0.155.1 runtime plus matching code-mode host in an isolated guest account with no saved model preference. Verify the live model catalog offers Luna/high, the native Settings display selects it, and a real turn requests that pair. A bounded read-only code-mode probe may inspect `typeof` and `ALL_TOOLS` but must never invoke an unrelated capability. A synthetic-media pass precedes the two private supplied recordings; record transient connection failures separately and rerun only after determining whether the final policy is implicated. Keep private screenshots, media hashes, account details and rollout contents out of Git.

When the Luna tool policy changes, rebuild the packaged native app and rerun both a bounded owned-tool inventory plus guarded edit/Undo/reopen and a real Luna/high trim/Undo/Stop/history regression. Verify process, thread-start and resume restrictions in unit tests. A synthetic probe showing no unowned nested tool in one turn is not proof that every direct or future upstream tool is absent. Inspect the actual guest window; never count a DOM assertion alone as visual acceptance.
