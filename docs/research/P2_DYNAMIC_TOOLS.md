# P2 host-defined tool boundary probe

Checked 2026-09-20 against the pinned official Codex 0.155.1 App Server and its generated protocol. [`thread/start.dynamicTools`](https://github.com/openai/codex/blob/rust-v0.155.1/codex-rs/app-server-protocol/src/protocol/v2/thread.rs) is experimental and requires `initialize.capabilities.experimentalApi`. The pinned [App Server dynamic-tool handler](https://github.com/openai/codex/blob/rust-v0.155.1/codex-rs/app-server/src/dynamic_tools.rs) sends `item/tool/call` to the host. This is a possible way to expose guarded editor tools without configuring an MCP server, whose resource helpers remain a P2-07 concern. It is not yet the product transport.

The ignored isolated Linux guest test runs the packaged official binary over stdio with no MCP server, a private app-owned ChatGPT credential copy, and a fresh context. It reads the live model catalog and requires `gpt-5.6-luna` with `high`. A namespaced host-defined read-only tool then receives exactly one `item/tool/call`; the bounded main-side callback validates its bare tool name, active thread and arguments. One actual code-mode `exec` cell computed `ALL_TOOLS.map(item => item.name)` and passed the resulting array to that host tool. The array contained only `codex_video_edit__editor_probe`. A private correlated rollout audit verified that exact code cell and found no other raw custom-tool name. The turn completed. No source media, project draft or user-host desktop was involved.

Earlier attempts remain failed evidence: a plain function definition led to a completed turn without a host call; a namespaced function reached the host but the first handler rejected it because `item/tool/call.params.tool` was the bare `editor_probe` name rather than the model-visible namespace-qualified name. A corrected namespaced call passed, followed by the stricter catalog, inventory and rollout-audited rerun. These observations apply to the tested turns only. They do not prove a complete upstream effective-tool allowlist, child inheritance, production project-thread resume, guarded draft dispatch, or a native Electron window. P2-07 and the full phase remain open.

The checked-in `tests/native/codex-dynamic-tools-probe.test.ts` requires an already authorized mode-600 guest-only credential profile and writes only bounded status and counts under ignored `test-results/`. It never reads or prints credential bytes. A future migration must preserve existing MCP-backed project threads, map the six owned dotted tool names to stable host-defined names, validate correlated requests before invoking the shared transaction service, and prove commit/Undo/reopen and source immutability in packaged Electron before changing product routing.
