# Reference rules

Read IMPLEMENTATION_NOTES.md first. Current images establish visual direction, previous images are alternatives. Keep each original image separate and retain its hash. Do not generate a contact sheet as a replacement for full-resolution files.

New references go under `references/screenshots/current/` with provenance, screen mapping, and correction notes in `manifest.json`. Inspect them with vision and update the mapped screen specifications, tasks, and tests. Do not copy proprietary application assets or claim generated mockups are executed native screenshots.

Screens without a direct full-screen reference are specified in SCREEN_COVERAGE.md. Build them from the same components and inspect the native result. Do not invent missing reference screenshots.
