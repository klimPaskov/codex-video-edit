# packages/codex-bridge

The implemented bootstrap client starts the official Codex 0.142.3 native executable over bounded stdio JSONL, initializes once, reads account metadata and discovers local skills. Model discovery requires a ChatGPT account response and uses the runtime catalog with bounded pagination. The client adds managed browser-login start/cancel/logout, reconciled account updates and rate-limit discovery. It exposes no generic RPC or edit operation to the renderer. Typed protocol inputs come from the pinned generator; consumed response fields are bounded and mapped without credentials or raw payloads.

The transport owns process lifetime, fixed safe errors, request matching and fail-closed server requests. Close waits for startup and process cleanup before reconnect; requests are never replayed. Tests may use a separate fake child, but the production client requires the exact official version. Main chooses a dedicated context and account directory and passes an environment allowlist; host account files are not copied.

This is the P2 runtime foundation. Native account/settings controls and runtime packaging passed the packaged Linux signed-out connection, login initiation/cancellation, reopen and scale checks with guest-only visual inspection. External browser launching was suppressed in the test; managed sign-in completion and authenticated model/usage/selection remain unverified. Application-owned experimental requests, a file-synced atomic project-thread binding, a bounded generation-aware stream reducer, idle unsubscribe, approval denial, and exact owned-MCP name/schema validation are wired into the production client. A real unauthenticated server test does not establish authenticated turn/edit or full P2 acceptance.

Generate types with `codex app-server generate-ts --experimental --out <directory>` using the pinned binary inside the isolated guest, transfer the generated text privately, then run `python scripts/sync_codex_types.py <generated-ts-directory>`. It verifies the reviewed dependency closure in `docs/contracts/codex-protocol.json`, adds explicit TypeScript import extensions and applies the pinned formatter. `--check` verifies the published copy without modifying it. Preserve original generated output privately. Upstream type shapes are unchanged; Apache-2.0 terms are retained in `licenses/CODEX-APACHE-2.0.txt`.

`resolveCodexRuntime(process.resourcesPath)` is main-only: it selects fixed resources/codex paths and verifies file types, pinned manifest and binary/licence hashes before returning the executable. It never launches a process or reads executable overrides. The guest build packages the binary and licence outside ASAR; no binary is committed. The protocol closure contains 205 generated types covering account/settings, thread/turn lifecycle, consumed stream notifications, server approvals, and owned MCP status. No authenticated acceptance follows from unit tests or signed-out checks.
